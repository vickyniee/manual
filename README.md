# Manual de Buenas Prácticas para el Trabajo Colaborativo Universitario

Este repositorio contiene el desarrollo y la versión final de un manual diseñado para optimizar el trabajo en equipo, mejorar la calidad académica y reducir el estrés en proyectos universitarios. El documento abarca desde la organización inicial hasta la presentación final, estableciendo estándares claros de trabajo.

# Estructura del Repositorio

El proyecto está organizado de la siguiente manera:
* /documentos: Contiene los archivos fuente en formato Word .docx y la versión final compilada del manual en formato .pdf.
* /imagenes: Recursos gráficos y capturas de pantalla utilizadas en el manual.
* /referencias: Material de apoyo y bibliografía consultada.

# Instrucciones de Uso o sea como usar el manual

Para consultar la versión oficial y estable de este manual:
1. Dirígete a la carpeta /documentos en la rama main de este repositorio.
2. Abre o descarga el archivo llamado Practicas.
3. No se recomienda leer los archivos .docx directamente desde GitHub, ya que la plataforma no renderiza correctamente las normas de formato APA (márgenes e interlineados). Por favor, utiliza siempre el PDF final

## Instrucciones de Contribución 

Este proyecto se gestiona estrictamente bajo la metodología de control de versiones. Para contribuir al manual, los integrantes del equipo deben seguir estos pasos

Para ver todos los commits estan en Actualizaciones, mi-seccion y lo ultimo al Main.

1. **Gestión de Tareas:** donde estan los issues con el Tablero Kanban del Proyecto [https://github.com/users/vickyniee/projects/2]
2. **Actualizar el entorno:** Asegurarse de tener la última versión del código base ejecutando git pull origin main.
3. **Creación de Ramas:** Todo trabajo nuevo debe realizarse en una rama separada. No se permite empujar o sea hacer el push directamente a main.
   * Comando: git checkout -b main
4. **Commits Trazables:** Cada commit debe documentar claramente el cambio y estar enlazado al número de el issue correcto (realizado ya)
5. **Pull Requests (PR):** Al finalizar la tarea, se debe abrir un PR hacia la rama main
6. **Revisión Cruzada:** El PR debe ser revisado y aprobado por otro integrante del equipo antes de ser fusionado Merged. En caso de conflictos en los archivos de texto, se deben resolver manualmente antes de la fusión.
